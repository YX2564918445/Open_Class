# 第 10 讲：定时器 0 与数码管秒表

> **配套例程**：[51_Project/10TimerStopwatch](../51_Project/10TimerStopwatch/)
>
> **面向读者**：自动化与信息工程学院学生科学与技术协会大一成员
>
> **硬件平台**：普中 A2 开发板（主控 STC89C52RC，11.0592 MHz 晶振）
>
> **前置要求**：已完成[第 9 讲：外部中断 1](09_外部中断1.md)，知道中断是怎么进来的、ISR 怎么写；了解[第 4 讲](04_数码管.md)的动态扫描与消隐。

第 9 讲做了一个秒表，但它靠的是软件延时：主循环里套着 125 轮扫描，每轮约 8 ms，扫完 125 轮就认为过去了 1 秒。

这个方法有两个毛病。第一是**不准**——`Delay_ms(1)` 真实耗时不等于 1 ms，误差一轮一轮累积，跑上几分钟就能差出好几秒。第二是**阻塞**——计时的那一秒里，`main` 除了扫数码管什么都干不了，想加个按键响应都得等这一秒过完。

这一讲把计时这件事交给硬件：**定时器**。它自己在那里一个机器周期加 1，加满了就通知 CPU 一声。CPU 只需要在中断里做一点点累加，剩下的时间想干什么干什么。

**本讲功能**：

| 状态 | 现象 |
| --- | --- |
| 上电 | 数码管显示 `-----0.0`，每 0.1 秒加 1，如 `-----1.3` → `----12.7` |
| 按 K3（P3.2） | 暂停计时；暂停期间小数点左右闪（0.3 秒一次），再按一次继续 |
| 按 K4（P3.3） | 清零，回到 `-----0.0` |
| 计满 1 小时 | 自动回到 0，从头再来 |

## 为什么需要定时器

### 软件延时的两个毛病

先看第 9 讲那套写法的结构：

```c
while(1)
{
    for(t = 0; t < 125; t++)        // 扫 125 轮，凑够"1 秒"
    {
        for(i = 0; i < 8; i++)      // 8 位数码管轮流点亮
        {
            SMG_Display(i + 1, disp_buf[i]);
            Delay_ms(1);
            SMG_Display(i + 1, 0x00);
        }
    }
    seconds++;                       // 认为过去了一秒
}
```

| 毛病 | 具体表现 |
| --- | --- |
| **不准** | `Delay_ms(1)` 真实可能是 1.02 ms，一轮 8 ms 变 8.16 ms，一圈 1 秒变 1.02 秒。一分钟就差了 1.2 秒 |
| **阻塞** | 这一秒里 `main` 卡在 `for` 循环里，按键、串口、蜂鸣器全都顾不上 |

误差不是哪一句写错了，而是"用指令数来当秒表"这件事本身就不精确：循环里加一句代码、换个优化等级、编译器把某句合并了，时间就变了。

### 定时器到底在数什么

STC89C52RC 内部有两个定时器/计数器（定时器 0 和定时器 1）。它们本质上是一个**会自动加 1 的 16 位计数器**，加满了（溢出）就置一个标志位，可以顺便产生中断。

定时器数的是什么？是**机器周期**：

```text
晶振 11.0592 MHz
      │
      ▼  12 分频（STC89C52RC 默认 12T 模式）
机器周期频率 921600 Hz
      │
      ▼
1 个机器周期 = 1 / 921600 ≈ 1.085 µs
```

所以从 0 开始数，数满 65536 次（16 位全 1 再加 1 就溢出）需要：

```text
65536 × 1.085 µs ≈ 71.1 ms
```

也就是说，**16 位定时器在最慢的设置下，一次最多只能定时 71 ms**。这个数字很关键：想做 1 秒的定时，必须靠中断反复累加。

> ⚠ **"12T 模式"是指 12 个晶振周期算一个机器周期。** STC 的部分型号可以在 STC-ISP 里设成 1T（速度快 12 倍），这时机器周期就变成 1/11.0592 µs ≈ 0.09 µs，初值全部要重算。普中 A2 出厂默认 12T，本讲按 12T 计算。

## 定时器的四个寄存器

### TMOD：选工作模式

`TMOD`（地址 0x89）不能位寻址，只能整字节写：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 7 | GATE（T1） | 门控位，0 = 软件启动即可 |
| 6 | C/T（T1） | 0 = 定时（数内部时钟），1 = 计数（数外部脉冲） |
| 5~4 | M1 M0（T1） | 模式选择 |
| 3 | GATE（T0） | 同上，定时器 0 |
| 2 | C/T（T0） | 同上 |
| 1~0 | M1 M0（T0） | 同上 |

高 4 位管定时器 1，低 4 位管定时器 0。本讲只用定时器 0，所以：

```c
TMOD &= 0xF0;       // 高 4 位（定时器1 的设置）原样保留，低 4 位清零
TMOD |= 0x01;       // 低 4 位 = 0001：GATE=0、C/T=0、M1M0=01 → 模式1
```

模式选择表：

| M1 M0 | 模式 | 说明 |
| --- | --- | --- |
| 0 0 | 模式 0 | 13 位定时器，为了兼容老芯片，基本不用 |
| 0 1 | 模式 1 | **16 位定时器**，本讲用这个 |
| 1 0 | 模式 2 | 8 位自动重装，**第 12 讲用它产生串口波特率** |
| 1 1 | 模式 3 | 拆分模式，很少用 |

> ⚠ **先 `&=` 再 `|=`，不要直接 `TMOD = 0x01`。** 直接赋值会把高 4 位（定时器 1 的设置）一起清掉。本讲不用定时器 1 所以看不出来，但第 12 讲串口一旦用了定时器 1，这种写法就会把波特率搞坏。

### TCON：启动与溢出标志

`TCON`（地址 0x88）可以位寻址，本讲只关心两位：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| TF0 | TCON.5 | 定时器 0 溢出标志，数满 65536 时硬件置 1（进中断后硬件自动清） |
| TR0 | TCON.4 | 定时器 0 运行控制，1 = 开始数，0 = 停 |

`TR0 = 1` 就是"放行"：从这一刻起，定时器每个机器周期加 1。

### IE：允许中断

| 位 | 名称 | 含义 |
| --- | --- | --- |
| ET0 | IE.1 | 允许定时器 0 中断（分闸） |
| EA | IE.7 | 总中断允许（总闸） |

两个都要开。定时器 0 的中断号是 **1**，入口地址 0x000B：

```c
void Timer0_ISR(void) interrupt 1
```

> ⚠ **中断号别和外部中断搞混。** 第 8、9 讲的外部中断 0/1 是 `interrupt 0` 和 `interrupt 2`，定时器 0 是 `interrupt 1`。五个中断源的编号和入口地址在第 8 讲那张表里，可以回去对一眼。

### 初值怎么算

标准公式：

```text
初值 = 65536 - 定时时间 ÷ 机器周期
```

本讲要 10 ms：

```text
10 ms = 10000 µs
10000 ÷ 1.085 ≈ 9216 （个机器周期）
65536 - 9216 = 56320 = 0xDC00
```

所以 `TH0 = 0xDC; TL0 = 0x00;`。

常见定时时间对照表（11.0592 MHz、12T）：

| 定时时间 | 需要的机器周期数 | 初值 | TH0 | TL0 |
| --- | --- | --- | --- | --- |
| 1 ms | 922 | 64614 | 0xFC | 0x66 |
| 2 ms | 1843 | 63693 | 0xF8 | 0xCD |
| 5 ms | 4608 | 60928 | 0xEE | 0x00 |
| **10 ms** | **9216** | **56320** | **0xDC** | **0x00** |
| 20 ms | 18432 | 47104 | 0xB8 | 0x00 |
| 50 ms | 46080 | 19456 | 0x4C | 0x00 |

> ⚠ **模式 1 不会自动重装初值。** 数到 65536 溢出后，计数器从 0 重新开始，不是从 0xDC00 开始。所以每次进中断都必须重新写一遍 `TH0`、`TL0`，这就是 ISR 开头那两句的作用。忘了写，中断间隔会变成 71 ms 而不是 10 ms——秒表会慢七倍。
>
> 模式 2 是 8 位自动重装（`TH` 存初值，溢出后硬件自动装回 `TL`），不需要软件重装，第 12 讲产生波特率用的就是它。

## 0.1 秒是怎么攒出来的

既然一次最多 71 ms，10 ms 的中断已经是"数得很快"了，那 0.1 秒怎么办？

```text
10 ms 中断 → tick10 + 1
            │
            ├─ 1 次 = 10 ms
            ├─ 5 次 = 50 ms
            └─ 10 次 = 100 ms = 0.1 秒 → tenth + 1，tick10 归零
```

代码就是这么写的：

```c
tick10++;
if(tick10 >= 10)
{
    tick10 = 0;
    tenth++;
}
```

**为什么不直接把定时器设成 0.1 秒一次？** 因为 0.1 秒需要 92160 个机器周期，早就超过了 16 位计数器能表示的最大值 65536。硬件做不到，只能软件分频。

> ⚠ **这里的 9216 和真实值有零点几的误差。** 精确算 10000 ÷ 1.0851 ≈ 9215.7，取 9216 是四舍五入。每个 10 ms 多算了约 0.3 µs，一小时累积 0.1 秒左右。加上中断响应本身还有 3~8 个机器周期的延迟，秒表一天差几秒是正常的。想更准就得改初值补偿，或者用带自动重装和校准的定时器——这是后面 STM32 里才需要操心的事。

## 显示：小数点与空位

本讲显示格式是 `123.4`，小数点固定在倒数第二位右边。段码表里最高位 `0x80` 就是小数点（dp 段）：

```c
buf[7] = smgd_code[v % 10];          // 十分位，不带小数点
buf[6] = smgd_code[v % 10] | 0x80;   // 秒个位，或上 0x80 点亮小数点
```

举例：`smgd_code[3]` 是 `0x4F`（显示 3），或上 `0x80` 变成 `0xCF`，同一个位置就显示成 `3.`。

**左边没有数字的位显示 "-" 而不是黑着**，这样一眼能看出秒表在哪一位、有没有停住：

```text
tenth = 5      →  -----0.5
tenth = 53     →  -----5.3
tenth = 1234   →  ----123.4
tenth = 12345  →  ---1234.5
```

`0x40` 是 "-" 的段码：共阴极数码管只有中间那一横（g 段）亮。段码表里 g 段对应 bit6，所以单独把 `0x40` 拿出来定义成宏。

> ⚠ **先全填 "-"，再往前填数字，顺序不能反。** 因为"填数字"是从右往左的，填到没有数字为止；如果先把数字填好再补 "-"，就不知道该在哪里停。

## volatile 与临界区

这一讲有两个以前没遇到过的问题，都和"中断随时会插进来"有关。

### volatile：告诉编译器"这个变量会自己变"

```c
volatile unsigned int tenth = 0;
```

`tenth` 在主函数里被读（显示用），在中断里被改（计时用）。如果没加 `volatile`，编译器分析主函数会发现"这段代码里根本没人改 `tenth`"，于是把它优化成只读一次、之后一直用寄存器里的旧值——**现象就是数字停在某个值不动了**。

加了 `volatile` 等于告诉编译器：这个变量可能在你看不见的地方被改，每次用都必须重新从内存读。

> ⚠ **判断标准：只要一个变量在中断里被改、在主函数里被读（或者反过来），就必须加 `volatile`。** 只在中断里用的变量（比如 `tick10`）不用加；只在主函数里用的也不用加。

### 临界区：16 位变量读一半被打断

51 是 8 位机，读一个 16 位的 `unsigned int` 要读两次（高字节、低字节）。如果正好读完低字节、还没读高字节的时候中断进来了，把 `tenth` 从 `0x00FF` 加成了 `0x0100`，主函数就会读出一个 `0x01FF` 这种根本不存在的数。

解决办法是把这两步包起来，中间不让中断插进来：

```c
EA = 0;
v = tenth;
EA = 1;
```

清零的时候同理：

```c
EA = 0;
tenth = 0;
tick10 = 0;
EA = 1;
```

> ⚠ **临界区要尽量短。** 关中断期间发生的定时器中断不会丢（TF0 标志会留着），但关得太久会影响别的中断响应。这里只有两三条赋值，没问题。

## 完整代码

`main.c` 全文如下（`Nixie.c/h`、`Delay.c/h` 与第 9 讲完全相同）：

```c
/* 调用头文件 */
#include "reg52.h"
#include "Nixie.h"
#include "Delay.h"

/* 引脚端口宏定义 */
// 独立按键（K1、K2 与串口共用，本例题程不用，只用 K3 和 K4）
sbit KEY_PAUSE = P3^2;		// K3：暂停 / 继续
sbit KEY_CLEAR = P3^3;		// K4：清零

#define SMG_MINUS 0x40		// 字符 "-" 的段码：共阴极数码管只有中间那一横（g 段）亮

/* 数码管左右方向开关 */
// 显示缓冲区里 buf[0] 放最左边一位，buf[7] 放最右边一位。
// 但 SMG_Display 的 position 对应板上哪一位，取决于排线的实际方向，
// 换一块板子可能整排左右颠倒。上板后发现数字反了，把下面的 0 改成 1，
// 显示部分其它地方都不用动。
#define SMG_DIR 0


/* 变量定义 */
unsigned char smgd_code[16]={0x3f,0x06,0x5b,0x4f,0x66,0x6d,0x7d,0x07,
							0x7f,0x6f,0x77,0x7c,0x39,0x5e,0x79,0x71};	// 共阴极数码管0~F段码表

// 下面这几个变量中断里会改、主函数里会读，必须加 volatile。
// 不加的话编译器可能认为"主函数里没人改它"，只读一次，数字就停着不动了
volatile unsigned int  tenth = 0;		// 0.1 秒的计数，显示时除以 10 就是秒数
volatile unsigned char running = 1;		// 1 = 正在计时，0 = 暂停
volatile unsigned char dot_on = 1;		// 小数点当前是否点亮（暂停时用来闪烁）

unsigned char tick10 = 0;				// 数 10ms 的次数，凑够 10 次就是 0.1 秒
unsigned char dot_cnt = 0;				// 小数点闪烁的计数
// tick10 和 dot_cnt 只在中断里用，主函数不碰，所以不用加 volatile


/**
  * @brief	定时器0中断服务函数：每 10ms 自动进来一次
  * @param	无
  * @retval	无
  * @note	本函数由硬件自动调用，主函数里不要调用它
*/
void Timer0_ISR(void) interrupt 1
{
	// 模式1 的定时器不会自动重装初值，所以每次进中断都要自己重新写一遍
	// 10ms 的初值：10ms / 1.085us ≈ 9216 个机器周期，65536 - 9216 = 56320 = 0xDC00
	TH0 = 0xDC;
	TL0 = 0x00;

	if(running == 1)					// 正在计时
	{
		// 为什么一次中断不是直接数 0.1 秒？
		// 因为 0.1 秒要 92160 个机器周期，早就超过 16 位定时器的最大值 65536 了，
		// 所以先在中断里数 10 次 10ms，凑够一次 0.1 秒
		tick10++;
		if(tick10 >= 10)				// 10 × 10ms = 100ms = 0.1 秒
		{
			tick10 = 0;
			tenth++;					// 0.1 秒计数加 1
			if(tenth >= 36000)			// 满 3600.0 秒（1 小时）就回到 0，防止数字溢出
			{
				tenth = 0;
			}
		}
		dot_on = 1;						// 计时过程中小数点一直亮着
	}
	else								// 暂停：数值不再变化
	{
		// 让小数点每 0.3 秒闪一下，一眼就能看出"停住了"，不是程序跑飞了
		dot_cnt++;
		if(dot_cnt >= 30)				// 30 × 10ms = 300ms
		{
			dot_cnt = 0;
			dot_on = !dot_on;			// 亮 → 灭 → 亮，来回翻转
		}
	}
}


/**
  * @brief	把秒表的数值转换成段码，放进显示缓冲区
  * @param	buf  显示缓冲区，buf[0] 对应最左边一位，buf[7] 对应最右边一位
  * @retval	无
  * @note	显示成 123.4 这种样子：小数点固定在倒数第二位右边，
  			左边还没有数字的位一律显示 "-"，而不是让它黑着
*/
void Update_DispBuf(unsigned char *buf)
{
	unsigned int v;			// 0.1 秒的计数
	unsigned char i;

	// 第一步：先把 8 位全部填成 "-"
	for(i = 0; i < 8; i++)
	{
		buf[i] = SMG_MINUS;
	}

	// 第二步：把数值读出来。
	// tenth 是 16 位的，51 一次只能读一个字节，如果读到一半中断把它加了 1，
	// 就会读出一个乱七八糟的数，所以先关中断，读完再打开
	EA = 0;
	v = tenth;
	EA = 1;

	// 第三步：从最右边一位开始往前填数字
	buf[7] = smgd_code[v % 10];			// 十分位
	v = v / 10;
	buf[6] = smgd_code[v % 10] | 0x80;	// 秒个位，或上 0x80 就点亮了它右边的小数点
	v = v / 10;

	// 第四步：剩下的秒十位、百位……只有真正有数字时才写进去，为 0 就留着刚才的 "-"
	i = 6;
	while(v > 0 && i > 0)
	{
		i--;
		buf[i] = smgd_code[v % 10];
		v = v / 10;
	}

	// 暂停时让小数点按 dot_on 闪；计时中 dot_on 一直是 1，小数点就常亮
	if(dot_on == 0)
	{
		buf[6] &= 0x7F;			// 把最高位清 0，小数点熄灭
	}
}


/**
  * @brief	按键扫描：K3 暂停/继续，K4 清零
  * @param	无
  * @retval	无
*/
void Key_Scan(void)
{
	// 51 单片机读引脚前要先写 1，把引脚拉成弱上拉，否则读回来可能一直是 0
	KEY_PAUSE = 1;
	KEY_CLEAR = 1;

	if(KEY_PAUSE == 0)					// K3 被按下了
	{
		Delay_ms(10);					// 消抖：先等 10ms 看它是不是真的还按着
		if(KEY_PAUSE == 0)
		{
			running = !running;			// 在"计时"和"暂停"之间来回切换
			if(running == 0)
			{
				dot_cnt = 0;			// 刚按下暂停：小数点从"亮"开始闪
				dot_on = 1;
			}
			else
			{
				dot_on = 1;				// 继续计时：小数点恢复常亮
			}
		}
		while(KEY_PAUSE == 0);			// 等松手，保证按住不放也只算按了一次
	}
	else if(KEY_CLEAR == 0)				// K4 被按下了
	{
		Delay_ms(10);
		if(KEY_CLEAR == 0)
		{
			// tenth 是两个字节，改到一半被中断打断的话会留下半截数据，
			// 所以先关总中断，清完再打开。
			// tick10 是中断里在用的分频计数，也一起放在临界区里清，免得正好清到一半又被加 1
			EA = 0;
			tenth = 0;
			tick10 = 0;
			EA = 1;
		}
		while(KEY_CLEAR == 0);
	}
}


/**
  * @brief	主函数
  * @param	无
  * @retval	无
*/
int main(void)
{
	unsigned char disp_buf[8];		// 显示缓冲区：buf[0] 最左，buf[7] 最右
	unsigned char i;

	/* 定时器0 初始化：产生 10ms 一次的中断 */
	TMOD &= 0xF0;		// TMOD 高 4 位是定时器1 的设置，原样保留；低 4 位清零
	TMOD |= 0x01;		// 定时器0 工作在模式1（16 位定时器）；GATE=0、C/T=0 表示"用内部时钟定时"
	TH0 = 0xDC;			// 10ms 初值：10ms / 1.085us ≈ 9216，65536 - 9216 = 0xDC00
	TL0 = 0x00;
	ET0 = 1;			// 允许定时器0 中断
	EA  = 1;			// 打开总中断
	TR0 = 1;			// 启动定时器0，它开始一个机器周期加 1

	while(1)
	{
		Update_DispBuf(disp_buf);		// 把最新的秒表数值转成段码

		// 动态扫描：8 位轮流点亮，轮一圈只要几毫秒，人眼看到的是同时显示
		for(i = 0; i < 8; i++)
		{
			// SMG_DIR=0 时 buf[0] 送位置1、buf[7] 送位置8；
			// SMG_DIR=1 时反过来送，用来应付左右排线相反的情况
			SMG_Display(SMG_DIR ? (8 - i) : (i + 1), disp_buf[i]);
			Delay_ms(1);						// 让这一位亮约 1ms
			SMG_Display(SMG_DIR ? (8 - i) : (i + 1), 0x00);	// 消隐：切下一位之前先把段码清 0，防止拖影
		}

		Key_Scan();		// 每扫描完一圈就查一次按键
	}
}
```

## 逐句讲解

### 定时器初始化（`main` 里最前面五句）

```c
TMOD &= 0xF0;
TMOD |= 0x01;
TH0 = 0xDC;
TL0 = 0x00;
ET0 = 1;
EA  = 1;
TR0 = 1;
```

顺序上有一点讲究：

1. 先设模式（`TMOD`），再写初值（`TH0`/`TL0`）——模式决定初值怎么用；
2. 先开中断（`ET0`、`EA`），再启动（`TR0`）。反过来的话，定时器一启动就可能立刻溢出进中断，而此时中断还没配置好。

> ⚠ **初值要在启动之前写。** 如果先 `TR0 = 1` 再写初值，定时器会从 0 开始数，第一次中断就不是 10 ms 而是 71 ms，秒表起步就慢一拍。

### ISR 里的两个分支

```c
if(running == 1)     // 计时：数 10 次 10ms，tenth 加 1
else                 // 暂停：数值不动，只让小数点闪
```

中断每 10 ms 都会进来，不管你在不在计时。所以暂停不是"关掉定时器"，而是"进来之后什么都不做"。

> ⚠ **不要用 `TR0 = 0` 来暂停。** 停下来容易，重新启动时定时器从哪儿开始数却不好控制，会出现半拍。让定时器一直跑、用标志位决定要不要累加，逻辑最干净。

### `Update_DispBuf` 的四步

```text
① 8 位全填 "-"                     先铺底色
② 关中断读出 tenth 到 v             拿到一个"完整"的数
③ buf[7] 十分位、buf[6] 秒个位+小数点  先填最低两位
④ 从 i=5 往前，有数字才填            高位没数字就留着 "-"
```

以 `tenth = 1234`（即 123.4 秒）为例：

```text
① buf[0..7] = - - - - - - - -
② v = 1234
③ buf[7] = 段码[4]        v = 123
   buf[6] = 段码[3] | 0x80 v = 12
④ i=6 → i=5: buf[5] = 段码[2]  v = 1
   i=5 → i=4: buf[4] = 段码[1]  v = 0
   v=0 退出循环，buf[0..3] 还是 "-"
```

显示结果：`- - - - 1 2 3. 4`，即 `----123.4`。

### `Key_Scan` 为什么每圈都调用

主循环扫完 8 位数码管大约 8 ms，所以按键最快 8 ms 被检查一次，完全够用（人按键至少几十毫秒）。

```c
while(KEY_PAUSE == 0);     // 等松手
```

这一句保证按住不放只算一次。代价是按住期间主循环卡在这里、数码管不刷新——**按住时数码管会暗一下**，松手立刻恢复。教学代码可以接受，想做得更好就得把扫描放进定时器中断里（那是后面的事了）。

## 实验现象

烧录后，你会看到：

1. **上电**：数码管显示 `-----0.0`，然后 `-----0.1`、`-----0.2`……每 0.1 秒跳一次，小数点常亮。
2. **计时到 10 秒以上**：显示变成 `----11.3` 这种样子——高位开始出现数字，横杠逐个被顶掉。
3. **按一下 K3**：数字定格，小数点开始闪烁（亮 0.3 秒、灭 0.3 秒）。再按一下 K3，小数点恢复常亮，数字接着走。
4. **按一下 K4**：数字回到 `-----0.0`，重新开始。
5. **按住 K3 或 K4 不放**：数码管会短暂变暗（主循环卡在等松手的那句上），松手后恢复。
6. **计满 1 小时**（3600.0 秒）：`tenth` 回到 0，显示 `-----0.0` 重新开始。

> ⚠ **暂停时秒表是"真停"还是"只是不显示"？** 是真停。暂停时 ISR 里的 `tenth++` 根本不执行，所以松手继续后不会"跳秒"。

## 常见问题

### 1. 数字一直停在 0 不动

90% 是 `tenth` 没加 `volatile`。编译器认为主函数里没人改它，只读了一次，之后一直用寄存器里的旧值。把 `unsigned int tenth = 0;` 改成 `volatile unsigned int tenth = 0;`。

### 2. 秒表走得明显偏快或偏慢

按顺序检查：

1. `TH0`/`TL0` 写对没有（10 ms 应该是 `0xDC00`）；
2. ISR 开头有没有重新写初值（模式 1 不自动重装）；
3. 芯片是不是被设成了 1T 模式（STC-ISP 下载时能看到"IRC 频率/时钟模式"）；
4. 晶振是不是 11.0592 MHz 而不是 12 MHz（12 MHz 下 10 ms 要 9216 → 实际变成 9216×(11.0592/12) 个周期，会偏快约 8%）。

### 3. 数码管显示的数字整排反了

比如 `123.4` 显示成 `4.321`。把 `main.c` 第 18 行的 `#define SMG_DIR 0` 改成 `1`。这个开关的作用是把 8 个位置整体反向送，其它代码不用动。

### 4. 数码管有位很暗，或者有拖影

- 位很暗：`Delay_ms(1)` 太短，或者这一位的限流电阻偏大，属硬件个体差异，问题不大；
- 拖影：消隐那句 `SMG_Display(..., 0x00)` 漏了。切换下一位之前必须把段码清 0，否则上一位的段码会短暂地"串"到下一位上。

### 5. 按 K3 一下，数字跳着变了好几次

`while(KEY_PAUSE == 0);` 那句等松手漏了。没有它，按住期间每次扫描都会检测到按下，一秒钟能被当成几十次。

### 6. 暂停后小数点不闪，一直亮着

- `dot_on` 有没有加 `volatile`；
- ISR 里 `dot_cnt >= 30` 的数值对不上（想快一点改小，想慢一点改大）；
- `Key_Scan` 里按下暂停时有没有把 `dot_cnt` 清 0（不清的话可能刚好从一半开始数，第一次闪会慢）。

### 7. 编译报错 `UNRESOLVED EXTERNAL SYMBOL`

本讲是多文件工程，记得把 `Nixie.c`、`Delay.c` 加进 Keil 的 Source Group（同第 4 讲）。只加了 `.h` 是不够的，`.h` 里只有声明，真正的函数体在 `.c` 里。
