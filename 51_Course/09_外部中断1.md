> **配套例程**：[51_Project/9ExternalINT1](../51_Project/9ExternalINT1/)

> **面向读者**：自动化与信息工程学院学生科学与技术协会大一成员
>
> **硬件平台**：普中 A2 开发板（主控 STC89C52RC，11.0592 MHz 晶振）
>
> **前置要求**：已完成[第 8 讲：外部中断 0](08_外部中断0.md)，理解中断的四个步骤、`interrupt` 关键字、下降沿触发；了解[第 4 讲](04_数码管.md)的动态扫描与消隐。

第 8 讲用的是下降沿触发：按一下键，进一次 ISR。那一讲也提了一句——如果把 `IT0` 设成 0，就变成了低电平触发，按键按着不动，ISR 会反复进入。

这一讲就专门用低电平触发做一件事：按住按键 → LED 持续闪烁；松手 → 闪烁停止，继续原来的工作。同时，这一讲的"原来的工作"不再是简单流水灯，而是一个**数码管秒表**——从 0 开始计时，显示在最右几位，空位不亮。

本讲的三个主题——低电平重复触发、秒表显示、ISR "冻结"主循环——合在一起，让你看到中断的另一面：它不只是"响应急事"，还可以用来**暂停主程序**。

**本讲功能**：

| 状态 | 现象 |
| --- | --- |
| 正常运行 | 数码管从右到左显示秒表（0 → 1 → 2 → …），空位不亮 |
| P3.3 被拉低（按键按下） | 秒表暂停，8 个 LED 持续闪烁（亮 200 ms → 灭 200 ms） |
| P3.3 恢复高电平（按键松开） | LED 停止闪烁，秒表从刚才的计数值继续 |

## 低电平触发：反复进入的 ISR

### 与下降沿触发的本质区别

把第 8 讲和第 9 讲的触发方式放在一张表里对比：

| | 下降沿（第 8 讲） | 低电平（第 9 讲） |
| --- | --- | --- |
| 设置 | `IT0 = 1` | `IT1 = 0` |
| 触发条件 | P3.2 从 1→0 的**瞬间** | P3.3 **持续为** 0 |
| ISR 调用次数 | 一次 | **反复进入** |
| 硬件清除 IE 标志 | 自动清除 | 不清除（IE1 反映 P3.3 电平） |
| 按键按着不松手 | 只触发一次 | 不断触发 |

下降沿触发关心的是"变化的瞬间"，低电平触发关心的是"当前的状态"。

在低电平触发下，流程是这样的：

```text
按键按下（P3.3 = 0）
    │
    ▼
CPU 进入 EX1_ISR()     ← 第 1 次
    │
    ├── LED 亮 200ms ──┤
    ├─ LED 灭 200ms ──┤
    │
    ▼
CPU 退出 ISR（执行 RETI）
    │
    ├─ 此时 IT1=0，硬件检查 P3.3
    │    │
    │    ├─ P3.3 仍然是 0（手指还按着）
    │    │    └─ IE1 = 1 → CPU 再次进入 EX1_ISR()  ← 第 2 次
    │    │
    │    └─ P3.3 变成了 1（手指松开了）
    │         └─ IE1 = 0 → 不触发，回到 main
```

这解释了本讲的核心现象：**按住 = 闪，松手 = 停**。

> ⚠ **第 8 讲说过"ISR 里不应该加延时"——但本讲不仅加了，还故意加了 200 ms。** 这是因为教学代码里 main 只有阻塞式延时扫描，没有实时性要求。低电平触发反复进入 ISR 的特性本身就决定了"ISR 占了全部 CPU 时间"，main 被彻底冻结——这种情况下 ISR 多停 200 ms 不会让事情更糟。真实项目里这种写法不可取，但理解原理需要从简单场景开始。

### 为什么 ISR 能"冻结" main

低电平触发 + 按键按住不松手的组合效果是：

```text
CPU 时间分配（按住按键期间）：

    ┌──── EX1_ISR ────┐  ┌──── EX1_ISR ────┐  ┌───  EX1_ISR ────┐
    │ LED亮200ms      │  │ LED亮200ms      │  │ LED亮200ms      │
    │ LED灭200ms      │  │ LED灭200ms      │  │ LED灭200ms      │
    │ RETI            │  │ RETI            │  │ RETI            │
    └─────────────────┘  └─────────────────┘  └─────────────────┘
    ↑ 硬件检测 P3.3=0    ↑ 硬件检测 P3.3=0    ↑ ……直到松手
    再次触发             再次触发

    main 在这期间：
    ┌──────── 一动不动 ────────────────┐
           （ISR 返回后只执行 1~2 条指令就又进了 ISR）
```

ISR 每次执行约 400 ms（200 ms 亮 + 200 ms 灭），返回 `main` 后 main 只来得及执行一两行代码（比如 `SMG_Display` 写一次段码），`P3.3` 还没变高，硬件检测到 `IE1 = 1`，再次跳进 ISR——`main` 里的秒表循环几乎完全停摆。直到松手、P3.3 变高、`IE1` 清 0，CPU 才真正回到 `main` 继续跑秒表。

这就是"低电平触发冻结主程序"的完整机制。

## 秒表原理

### 时间积累

`main` 的 `while(1)` 循环结构是：

```c
while(1)
{
    Update_DispBuf(seconds, disp_buf);     // 把秒数转为显示缓冲区

    for(t = 0; t < 125; t++)               // 动态扫描约 1 秒
    {
        for(i = 0; i < 8; i++)
        {
            SMG_Display(i + 1, disp_buf[i]);
            Delay_ms(1);
            SMG_Display(i + 1, 0x00);       // 消隐
        }
    }

    seconds++;                              // 秒数 +1
}
```

一轮扫描约 8 ms（8 位 × 1 ms），扫描 125 轮的耗时为：

```text
125 × 8 ms = 1000 ms ≈ 1 秒
```

每过约 1 秒，`seconds++`，再更新显示缓冲区，继续扫描……如此循环。

> ⚠ **这个 1 秒是不精确的。** `Delay_ms(1)` 的实际延时略大于 1 ms（约 1.02 ms，和晶振频率、指令循环有关），加上 `SMG_Display` 的函数调用开销，实际误差累积后可能偏慢。想要精确计时，需要定时器——这是后续讲次的内容。

### 显示缓冲区：空位不亮

`Update_DispBuf` 负责把秒数值（如 `seconds = 42`）转换成 8 字节的段码数组：

```c
void Update_DispBuf(unsigned int sec, unsigned char *buf)
{
    unsigned char i;
    unsigned int temp = sec;
    for(i = 0; i < 8; i++)
    {
        if(temp == 0 && i > 0)
        {
            buf[7 - i] = 0x00;       // 空位不亮
        }
        else
        {
            buf[7 - i] = smgd_code[temp % 10];
        }
        temp /= 10;
    }
}
```

以 `seconds = 42` 为例：

| i | `temp` | `temp % 10` | 写入位置 | 写入值 | 数码管显示 |
| --- | --- | --- | --- | --- | --- |
| 0 | 42 | 2 | buf[7]（最右位） | `smgd_code[2]` = 0x5B | `2` |
| 1 | 4 | 4 | buf[6] | `smgd_code[4]` = 0x66 | `4` |
| 2 | 0 | 0 | buf[5] | `smgd_code[0]` = 0x3F | `0` |
| 3 | 0 | — | buf[4] | `0x00`（temp=0 且 i>0） | 不亮 |

这里 `if(temp == 0 && i > 0)` 是关键：当 `temp` 变成 0 之后，说明更高的位已经全是 0 了。但它保留 `i = 0` 时仍然写 `0`（个位），`i = 1` 时写入十位，再往上才全灭——这样 **42 显示为 `42` 而不是 `00000042`**。如果 `seconds = 0`，只会在最右位显示 `0`，其余 7 位全灭。

> ⚠ `buf[7 - i]` 而不是 `buf[i]`，是因为数码管的 `position` 约定是"1 是最右位，8 是最左位"。`buf[7]` 对应 position 1（最右），`buf[0]` 对应 position 8（最左）。

## 完整代码

文件：[51_Project/9ExternalINT1/main.c](../51_Project/9ExternalINT1/main.c)

```c
/* 调用头文件 */
#include "reg52.h"
#include "Nixie.h"
#include "Delay.h"

/* 引脚端口宏定义 */
// LED接在P2.0~P2.7，共阳极，低电平点亮
#define LED P2

/* 变量定义 */
unsigned char smgd_code[16]={0x3f,0x06,0x5b,0x4f,0x66,0x6d,0x7d,0x07,
							0x7f,0x6f,0x77,0x7c,0x39,0x5e,0x79,0x71};	// 共阴极数码管0~F段码表


/**
  * @brief	外部中断1服务函数（低电平触发）
  * @param	无
  * @retval	无
*/
void EX1_ISR(void) interrupt 2
{
	LED = 0x00;			// 全部LED点亮
	Delay_ms(200);
	LED = 0xFF;			// 全部LED熄灭
	Delay_ms(200);
	// 低电平触发：P3.3保持低电平时CPU反复进入此ISR，形成连续闪烁
}


/**
  * @brief	将秒数值转换为数码管显示缓冲区（右对齐，空位不亮）
  * @param	sec  当前秒数值
  * @param	buf  显示缓冲区（buf[0]对应位置8，buf[7]对应位置1）
  * @retval	无
*/
void Update_DispBuf(unsigned int sec, unsigned char *buf)
{
	unsigned char i;
	unsigned int temp = sec;
	for(i = 0; i < 8; i++)
	{
		if(temp == 0 && i > 0)
		{
			buf[7 - i] = 0x00;		// 空位不亮
		}
		else
		{
			buf[7 - i] = smgd_code[temp % 10];
		}
		temp /= 10;
	}
}


/**
  * @brief	主函数
  * @param	无
  * @retval	无
*/
int main(void)
{
	unsigned int seconds = 0;		// 秒表计数值
	unsigned char disp_buf[8];		// 显示缓冲区
	unsigned char i;
	unsigned int t;

	/* 初始化外部中断1 */
	IT1 = 0;		// 外部中断1 低电平触发
	EX1 = 1;		// 使能外部中断1
	EA  = 1;		// 开启全局中断

	while(1)
	{
		Update_DispBuf(seconds, disp_buf);

		// 动态扫描刷新 ~1秒
		for(t = 0; t < 125; t++)
		{
			for(i = 0; i < 8; i++)
			{
				SMG_Display(i + 1, disp_buf[i]);	// 按位发送显示数据
				Delay_ms(1);						// 等待显示稳定
				SMG_Display(i + 1, 0x00);			// 消隐
			}
		}

		seconds++;
	}
}
```

## 逐句讲解

### 中断初始化（第 67 ~ 69 行）

```c
/* 初始化外部中断1 */
IT1 = 0;        // 外部中断1 低电平触发
EX1 = 1;        // 使能外部中断1
EA  = 1;        // 开启全局中断
```

和第 8 讲唯一的区别：`IT1 = 0`（低电平触发）而不是 `IT1 = 1`（下降沿触发）。三个寄存器位的含义：

| 设置 | 含义 |
| --- | --- |
| `IT1 = 0` | INT1 低电平触发——P3.3 持续为 0 时反复触发 |
| `EX1 = 1` | 打开 INT1 中断的分闸 |
| `EA = 1` | 打开全局中断总闸 |

### ISR：`void EX1_ISR(void) interrupt 2`

```c
void EX1_ISR(void) interrupt 2
```

- 中断号是 `2`（INT1），不是第 8 讲的 `0`（INT0）。两个外部中断的 `interrupt` 编号不同，入口地址也不同（INT1 入口是 0x0013）。
- 触发引脚是 P3.3，对应普中 A2 的 K4 按键。

### ISR 内部：亮 200 ms + 灭 200 ms

```c
LED = 0x00;
Delay_ms(200);
LED = 0xFF;
Delay_ms(200);
```

和第 8 讲 ISR 的区别在于：

| 第 8 讲（INT0） | 第 9 讲（INT1） |
| --- | --- |
| `for` 循环控制 3 次闪烁 | 不用循环——每次进入 ISR 只闪一次（亮→灭） |
| ISR 返回后就回 main | ISR 返回后，若 P3.3=0，硬件立即再次触发 → 又一次亮→灭 |
| 闪烁次数由代码决定（3 次） | 闪烁次数由"按住多久"决定 |

按住 2 秒 → ISR 被触发约 `2000ms ÷ 400ms ≈ 5 次` → LED 闪约 5 次。按住越久闪越多。

> ⚠ **闪烁的节奏不是完美的 200 ms + 200 ms。** ISR 每次执行还包含 ISR 入口的寄存器保存（PUSH）和出口的恢复（POP）+ `RETI`，以及回到 main 后执行的那 1~2 条指令再被中断的开销。这些额外的机器周期会让每个"亮灭周期"略长于 400 ms，但肉眼几乎看不出来。

### 秒表循环：三个嵌套层次

```c
while(1)
{
    Update_DispBuf(seconds, disp_buf);        // ① 秒数→段码数组

    for(t = 0; t < 125; t++)                  // ② ~1秒的动态扫描
    {
        for(i = 0; i < 8; i++)                // ③ 8位数码管逐一刷新
        {
            SMG_Display(i + 1, disp_buf[i]);
            Delay_ms(1);
            SMG_Display(i + 1, 0x00);
        }
    }

    seconds++;                                 // ④ 秒数+1
}
```

三层嵌套的结构：

```text
while(1)                     ← 最外层：永不停止
  │
  ├── 转换秒数 → 段码
  │
  ├── for(t: 0→124)         ← 中层：125 轮扫描 ≈ 1 秒
  │     │
  │     └── for(i: 0→7)     ← 最内层：一轮扫描 8 位
  │           │
  │           ├── 位选
  │           ├── 段选
  │           ├── 延时 1ms
  │           └── 消隐
  │
  └── seconds++
```

把 125 轮扫描放在计数之前，而不是每扫描一轮就计一次，是因为一轮扫描仅约 8 ms——如果每 8 ms 计一次，秒表会飞速跑到几百。`Delay_ms` 不准，但作为教学 demo 足够了。

### `Update_DispBuf` 的算法

逐行看 `seconds = 42` 时的执行过程：

```
temp = 42
i=0: temp=42, 42%10=2 → buf[7]=段码[2], temp=4
i=1: temp=4,   4%10=4 → buf[6]=段码[4], temp=0
i=2: temp=0, i>0 → buf[5]=0x00, temp=0
i=3: temp=0, i>0 → buf[4]=0x00, temp=0
...
i=7: temp=0, i>0 → buf[0]=0x00
```

结果：buf[7]=2的段码, buf[6]=4的段码, buf[5~0]=0x00。数码管显示 `    42`（右对齐，前 6 位不亮）。

## 实验现象

烧录后，你会看到：

1. **上电后**：数码管最右位显示 `0`，然后约 1 秒后跳到 `1`，再 1 秒后跳到 `2`……秒表正常运行，空的高位不亮（如显示 `42` 而不是 `00000042`）。
2. **按下 K4（P3.3）并按住不放**：秒表显示**定格**在当前数值，LED 全部闪烁（约 200 ms 亮 → 200 ms 灭 → 循环），只要不松手就一直闪。
3. **松开 K4**：LED 立即停止闪烁，秒表从定格的那个数值**继续累加**（比如按下去时是 5，松手后接着从 5 到 6、7、8……）。
4. **秒表计到 65535 之后**：`seconds` 是 `unsigned int`（0~65535），溢出后回到 0（数码管重新显示 `0`）。

## 常见问题

### 1. 按住 K4 但 LED 不闪

1. 检查 K4 跳线帽有没有冲突；
2. `IT1 = 0` 有没有写？写成 `IT1 = 1` 就变成了下降沿触发——按一下只闪一次（亮灭各 200 ms），不会持续；
3. `EX1 = 1` 和 `EA = 1` 缺了没有；
4. 中断号写对没：INT1 是 `interrupt 2`，不是 `interrupt 0`。

### 2. 按住 K4 时秒表还在走

如果你的代码是对的但秒表仍然在走，说明 ISR 没有被反复触发。检查 `IT1 = 0` 是否正确——如果错写成了 `IT1 = 1`，ISR 只触发一次，main 在 400 ms 后恢复运行，秒表自然继续走。

### 3. 按住 K4 时数码管灭了或乱码

LED 和数码管共用 P2 口的位选引脚（P2.2~P2.4）。ISR 里 `LED = 0x00` 把整个 P2 口写成了全 0，位选信号被覆盖。ISR 执行期间数码管显示的是什么取决于 `SMG_Display` 最后一次写入的状态残留在硬件上。这是正常的硬件干扰——只要松手、main 恢复扫描，数码管会恢复正常。

> 这个现象恰好说明了"共用引脚"的问题：当一个引脚被两个外设共享时，其中一个的驱动会干扰另一个。解决方法是分时复用（本讲恰好是分时的——ISR 期间 main 冻结，不会同时操作 P2），或者用片选/使能信号隔离。

### 4. 松手后秒表跳了好几秒

按住按键的期间，虽然 `main` 被冻结了，但 `seconds` 变量本身没有被改。松手后秒表接着走，不应该跳。如果你观察到跳了好几秒，检查 ISR 里是否不小心改了 `seconds` 变量（第 8 讲提过的"变量共享"问题）。

### 5. 秒表走得明显偏快或偏慢

软件延时不准是正常现象。`Delay_ms(1)` 的实际耗时受晶振精度、编译优化等级、中断开销的影响。想要精确计时，必须用定时器——后面的讲次会覆盖。

### 6. 编译报错 `UNRESOLVED EXTERNAL SYMBOL`

本讲是多文件工程，记得把 `Nixie.c` 和 `Delay.c` 加入 Keil 工程的 Source Group 1（和第 4 讲一样）。

## 从第 8 讲到第 9 讲

| 方面 | 第 8 讲（INT0） | 第 9 讲（INT1） |
| --- | --- | --- |
| 触发方式 | `IT0 = 1`（下降沿） | `IT1 = 0`（低电平） |
| 中断号 | `interrupt 0` | `interrupt 2` |
| 触发引脚 | P3.2（K3） | P3.3（K4） |
| 触发次数（按住不放） | 1 次 | 反复进入 |
| ISR 动作 | 闪烁 3 次（`for` 循环） | 每进一次亮灭各 200 ms |
| 对 main 的影响 | ISR 返回后继续 | ISR 执行期间 main 几乎冻结 |
| main 的任务 | 流水灯 | 数码管秒表 |
| 多文件 | 单文件 | main + Nixie + Delay |
| 显示输出 | LED | LED + 数码管 |

**低电平触发的双重性**：它既可以用来做"紧急停机"（按住 → 一切暂停 → 松手恢复），也可能在你不想要的时候反复触发（忘了设成下降沿）。两种触发方式本身没有好坏——选择哪一种取决于你要实现什么功能。
