> **配套例程**：[51_Project/8ExternalINT0](../51_Project/8ExternalINT0/)
>
> **面向读者**：自动化与信息工程学院学生科学与技术协会大一成员
>
> **硬件平台**：普中 A2 开发板（主控 STC89C52RC，11.0592 MHz 晶振）
>
> **前置要求**：已完成[第 2 讲：流水灯](02_流水灯.md)，理解端口输出与软件延时；了解[第 3 讲](03_按键控制LED.md)的按键消抖。

前 7 讲里，程序是"一条路走到黑"的：从头到尾按顺序执行，`Delay_ms` 一卡就是几百毫秒，CPU 在这期间什么也干不了。如果流水灯正在往左移，你按了一个键——不好意思，得等当前的 `Delay_ms(500)` 跑完才能轮到你。

这一讲引入一个根本性的改变：**中断**。让 CPU 在执行流水灯的过程中，能随时停下来响应一个外部事件——按键按下——然后再若无其事地回到刚才停下的地方继续。

中断是单片机区别于"高级循环器"的分水岭。理解它，需要同时理解**硬件触发机制**和**软件服务流程**两个层面。

**本讲功能**：

| 状态 | 现象 |
| --- | --- |
| 正常运行 | LED 流水灯（左移 → 右移 → 循环） |
| P3.2 按键按下（下降沿） | 全部 LED 闪烁 3 次（亮 500 ms → 灭 500 ms），闪烁完毕后继续流水灯 |

## 中断：CPU 的"紧急响应"

### 中断的概念

看一个类比：你正在看书（流水灯循环），手机响了（P3.2 按键按下）。你的动作是：

1. 在书页角折个标记（保存现场）——CPU 把下一条指令的地址压入堆栈；
2. 接电话（执行 ISR）——CPU 跳到中断服务函数去执行；
3. 挂断电话（ISR 执行完）——CPU 执行 `RETI` 指令；
4. 翻回刚才那页继续看（恢复现场）——CPU 从堆栈弹出地址，接着执行刚才被打断的地方。

整个过程对"看书"这件事是**透明的**——`main` 函数里加不加中断，代码本身不需要改（流水灯的 `for` 循环和 `Delay_ms` 完全不动）。

### 51 的中断源与优先级

STC89C52RC 有 6 个中断源，本讲用到的是 **INT0（外部中断 0）**：

| 中断源 | 入口地址 | `interrupt` 编号 | 触发引脚 | 本讲 |
| --- | --- | --- | --- | --- |
| INT0（外部中断 0） | 0x0003 | 0 | P3.2 | ✅ |
| TF0（定时器 0） | 0x000B | 1 | — | 否 |
| INT1（外部中断 1） | 0x0013 | 2 | P3.3 | 第 9 讲 |
| TF1（定时器 1） | 0x001B | 3 | — | 否 |
| RI/TI（串口） | 0x0023 | 4 | P3.0/P3.1 | 否 |
| TF2（定时器 2） | 0x002B | 5 | — | 否 |

> ⚠ **`interrupt` 后面的数字不是随便写的。** Keil C51 通过这个编号知道 ISR 的入口地址，生成对应的中断向量。如果写成 `interrupt 1`，函数就会被当作定时器 0 的中断——类型完全不对，功能完全错误。

### 中断的四个步骤

要让一个外部中断真正生效，需要完成四件事：

```text
① 选择触发方式（IT0 = 1：下降沿触发）
          ↓
② 打开该中断的使能位（EX0 = 1）
          ↓
③ 打开全局中断开关（EA = 1）
          ↓
④ 编写中断服务函数（void xxx(void) interrupt 0）
```

任何一步漏掉，中断都不会触发。初学者最常见的 bug 就是忘了 `EA = 1`——每个中断都开好了，但总闸没拉，一个都不响应。

## 外部中断的配置

### TCON：触发方式

`TCON`（Timer/Counter Control Register）的低 4 位控制两个外部中断的触发方式：

| 位 | 名称 | 作用 | 本讲设置 |
| --- | --- | --- | --- |
| TCON.0 | IT0 | INT0 触发方式选择 | **1**（下降沿触发） |
| TCON.1 | IE0 | INT0 中断标志（硬件置 1） | 自动 |
| TCON.2 | IT1 | INT1 触发方式选择 | 第 9 讲用 |
| TCON.3 | IE1 | INT1 中断标志 | 第 9 讲用 |

`IT0 = 1`：当 P3.2 引脚上出现一个**下降沿**（从高电平变到低电平的瞬间），硬件自动把 `IE0` 置 1，向 CPU 发出中断请求。CPU 响应后硬件自动清除 `IE0`。

`IT0 = 0`：**低电平触发**。只要 P3.2 是低电平，CPU 就会反复进入中断——这正是第 9 讲要用的模式。

```c
IT0 = 1;    // 下降沿触发
```

### IE：中断开关

`IE`（Interrupt Enable Register）是中断的"总闸 + 分闸"：

| 位 | 名称 | 作用 | 本讲设置 |
| --- | --- | --- | --- |
| IE.7 | EA | 全局中断使能（总闸） | **1** |
| IE.2 | ET2 | 定时器 2 中断使能 | 0 |
| IE.3 | ES | 串口中断使能 | 0 |
| IE.1 | ET1 | 定时器 1 中断使能 | 0 |
| IE.0 | EX1 | 外部中断 1 使能 | 0 |
| IE.4 | ET0 | 定时器 0 中断使能 | 0 |
| IE.5 | EX0 | 外部中断 0 使能 | **1** |

```c
EX0 = 1;    // 打开 INT0 分闸
EA  = 1;    // 打开总闸
```

> ⚠ **`IT0`、`EX0`、`EA` 都是在 `reg52.h` 里用 `sbit` 声明的位变量。** 你可以直接像操作 `LED1` 那样给它们赋值 0 或 1，不需要去记 `TCON` 和 `IE` 的地址。`reg52.h` 帮你做了这件事。

### 触发方式的选择

| 触发方式 | `IT0` 值 | 触发条件 | ISR 调用次数 | 适用场景 |
| --- | --- | --- | --- | --- |
| 下降沿 | 1 | P3.2 从高变低的那一瞬间 | **1 次**（硬件自动清除 IE0） | 按键、传感器脉冲 |
| 低电平 | 0 | P3.2 保持低电平的**整个期间** | **反复进入**（CPU 退出 ISR 后立即再次触发） | 紧急停机、持续报警（第 9 讲） |

本讲用下降沿：按一次键 → 触发一次中断 → 闪烁 3 次 → 继续流水灯。

> ⚠ 如果你把 `IT0` 设成 0（低电平触发），即使只按一下键，只要手指还没松开（几百毫秒），ISR 就会被反复触发几十次——不是 3 次闪烁，而是没完没了的闪烁。第 9 讲正是利用了这个特性。

## 完整代码

文件：[51_Project/8ExternalINT0/main.c](../51_Project/8ExternalINT0/main.c)

```c
/* 调用头文件 */
#include "reg52.h"
#include <intrins.h>	// 提供_nop_()函数

/* 引脚端口宏定义 */
// LED接在P2.0~P2.7，共阳极，低电平点亮
#define LED P2

/* 函数声明 */
void Delay_ms(unsigned int ms);

/**
  * @brief	外部中断0服务函数（下降沿触发）
  * @param	无
  * @retval	无
*/
void EX0_ISR(void) interrupt 0
{
	unsigned char j;
	/* 所有LED闪烁3次（亮500ms→灭500ms） */
	for(j = 0;j < 3;j++)
	{
		LED = 0x00;			// 全部LED点亮
		Delay_ms(500);
		LED = 0xFF;			// 全部LED熄灭
		Delay_ms(500);
	}
}


/**
  * @brief	主函数
  * @param	无
  * @retval	无
*/
int main(void)
{
	unsigned char i,led;

	led = 0x01;		// 0000 0001 作为移位的基础

	/* 初始化外部中断0 */
	IT0 = 1;		// 外部中断0 下降沿触发
	EX0 = 1;		// 使能外部中断0
	EA  = 1;		// 开启全局中断

	while(1)
	{
		// LED1→LED8（左移）
		for(i = 0;i < 8;i++)
		{
			LED = ~(led << i);
			Delay_ms(500);			// 保证每个LED点亮500ms
		}
		// LED7→LED2（右移）（避免两头LED重复点亮）
		for(i = 6;i > 0;i--)
		{
			LED = ~(led << i);
			Delay_ms(500);			// 保证每个LED点亮500ms
		}
	}
}


/**
  * @brief	延时函数：产生一段时间的延时效果
  * @param	ms 想要产生延时的毫秒数
  * @retval	无
*/
void Delay_ms(unsigned int ms)
{
	unsigned int i,j;
	for(i = ms;i > 0;i--)
	{
		// 11.0592MHz晶振，921个机器周期约为1ms
		for(j = 110;j > 0;j--)
		{
			_nop_();		// 空操作，消耗1个机器周期
		}
	}
}
```

## 逐句讲解

### 中断初始化（第 42 ~ 44 行）

```c
/* 初始化外部中断0 */
IT0 = 1;        // 外部中断0 下降沿触发
EX0 = 1;        // 使能外部中断0
EA  = 1;        // 开启全局中断
```

这三行放在 `while(1)` 之前，属于"初始化"阶段，只执行一次。顺序可以互换（都是独立的位操作），但习惯上**先配置触发方式再开使能**，避免在配置过程中被意外触发。

### ISR：`void EX0_ISR(void) interrupt 0`

```c
void EX0_ISR(void) interrupt 0
```

这是本讲最重要的新语法。逐部分拆解：

| 部分 | 含义 |
| --- | --- |
| `void` | ISR 没有返回值（它不返回任何东西给调用者，因为根本没有调用者） |
| `EX0_ISR` | 函数名，可以随便起（叫 `INT0_Handler` 也行），但 `interrupt 0` 不能改 |
| `(void)` | ISR 不接受参数（没有调用者给它传参） |
| `interrupt 0` | **中断号 0**，告诉编译器这个函数是 INT0 的中断服务函数 |

编译器看到 `interrupt 0`，会在中断向量表里把这个函数的地址填入 0x0003 位置。当 INT0 中断发生时，硬件自动跳到 0x0003，再通过跳转指令进入这个函数。

> ⚠ **ISR 不能被 `main` 或其他函数直接调用。** 你写 `EX0_ISR()` 编译器不会阻止（只会警告），但这不是"触发中断"，而是"普通函数调用"——和按键按不按、P3.2 什么电平完全无关。

### ISR 内部：闪烁 3 次

```c
void EX0_ISR(void) interrupt 0
{
    unsigned char j;
    for(j = 0; j < 3; j++)
    {
        LED = 0x00;         // 全部LED点亮
        Delay_ms(500);
        LED = 0xFF;         // 全部LED熄灭
        Delay_ms(500);
    }
}
```

- `LED = 0x00`：P2 口全部写 0，共阳 LED 全部点亮；
- `LED = 0xFF`：P2 口全部写 1，共阳 LED 全部熄灭；
- `Delay_ms(500)` 在 ISR 里同样可用——延时期间 CPU 卡在 ISR 里，不会返回 `main`。

> ⚠ **这个 ISR 的总执行时间约为 3 秒。** 本讲这样做是因为流水灯的 `main` 里也只有延时，ISR 久一点没影响。**不意味着"ISR 里可以随意写延时"。** 真实项目里，ISR 应该尽快执行完，把耗时操作交给主循环或任务队列——否则其他中断可能丢失、系统实时性崩溃。

### 主循环：流水灯（和[第 2 讲](02_流水灯.md)完全相同）

```c
while(1)
{
    for(i = 0; i < 8; i++)
    {
        LED = ~(led << i);
        Delay_ms(500);
    }
    for(i = 6; i > 0; i--)
    {
        LED = ~(led << i);
        Delay_ms(500);
    }
}
```

LED 从 P2.0 亮到 P2.7（左移），再从 P2.6 亮回 P2.1（右移），循环往复。这段代码和第 2 讲一字不差，详细讲解请回看[第 2 讲：流水灯](02_流水灯.md#逐句讲解)。

加了中断之后，这段代码本身一行都不用改——这就是中断的"透明性"。

## 实验现象

烧录后，你会看到：

1. **上电后**：LED 从左到右、再从右到左循环点亮，每个 LED 亮约 500 ms。
2. **按下 K3（P3.2）的一瞬间**：流水灯**立即暂停**，8 个 LED 全部闪烁 3 次（亮 500 ms → 灭 500 ms）× 3 = 约 3 秒。
3. **闪烁完毕后**：流水灯从刚才被打断的位置**继续**执行。
4. **在闪烁期间再次按下 K3**：不会被响应。因为 CPU 正在 ISR 里执行（全局中断虽然在硬件层面自动暂时关闭了同级中断，更重要的是 ISR 内没有"返回"）——等当前 ISR 执行完、回到 `main` 之后，下一次按键的下降沿才会被捕获。

## 常见问题

### 1. 按下 K3 没反应，流水灯照常运行

按顺序排查：

1. **K3 的跳线帽是否和红外接收头冲突？** P3.2 与红外共用，拔掉红外跳线帽再试；
2. `EA = 1` 有没有写？总闸没开等于所有中断全关；
3. `IT0 = 1` 有没有写？默认值可能是 0（低电平触发），此时按键按下 P3.2 确实变低了，但低电平触发的 ISR 会反复进入、可能表现异常；
4. `interrupt 0` 写对了没有？写成 `interrupt 1` 或没写 `interrupt`，函数就只是普通函数，不会被硬件触发。

### 2. 按一下键，LED 闪了无数次

`IT0 = 1` 写成了 `IT0 = 0`（低电平触发）。在低电平模式下，只要 P3.2 保持低电平（你的手指还没松开），CPU 退出 ISR 后硬件检测到 IE0 仍是 1，会立即再次触发 ISR——结果就是没完没了的闪烁。

### 3. 流水灯回到 main 后从头开始了

中断返回后，程序是接着被打断的那一行**往后执行**，不会从头开始。如果你看到的效果像"从头开始"，检查一下是不是在 ISR 里不小心改了 `i` 或 `led` 这些全局/局部变量。ISR 和 `main` 共用同一组变量，ISR 里改了 `i`，`main` 的循环就会跳位。

> ⚠ **ISR 里用了 `unsigned char j`（局部变量）是安全的**——局部变量存在寄存器或栈里，不会影响 `main` 的同名变量。但如果不用局部变量而直接改了全局变量，就会产生这种 bug。这是"变量共享"问题的雏形，学到多任务/RTOS 时还会深入讲。

### 4. 编译报错 `INTERRUPT 0 ALREADY USED`

你的工程里定义了两个 `interrupt 0` 的函数。Keil C51 不允许同一个中断号被多个函数声明。检查是否重复定义了 ISR，或者 `STARTUP.A51` 里是否也定义了一个同名中断入口。

### 5. 在 ISR 闪烁期间，再按一次键，闪烁次数没重置

这是下降沿触发的正常行为——一次下降沿触发一次 ISR。ISR 执行期间即使 P3.2 上再出现下降沿，由于 51 默认情况下同级中断不会被嵌套，这次触发会被挂起（IE0 置 1），等当前 ISR 返回后**再进入一次**。所以如果你在第一次闪烁期间又按了一次键，会看到闪烁完 3 次后又自动闪了 3 次。

3. 在 ISR 里加一个计数变量（全局变量），每进一次 ISR 计数 +1，然后用数码管显示——验证你的确只进了一次 ISR；
